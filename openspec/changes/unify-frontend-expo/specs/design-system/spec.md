# Spec Delta

## Purpose

统一设计系统 —— 玩家端与管理后台共用同一套共享组件库与设计 token 单一来源，消除双份 UI 实现与双份主题定义。

## ADDED Requirements

### Requirement: 单一组件库

玩家端与管理后台 SHALL 由同一个共享组件库渲染；两个应用内 MUST NOT 各自复制实现同一组件（业务页面只组装组件库原语）。

#### Scenario: 新增后台组件入库
- **WHEN** 后台需要一个新 UI 原语（如徽章）
- **THEN** 它在共享组件库中实现并被后台引用，而不是后台本地私有一份

### Requirement: 设计 token 单一来源

颜色、间距、字号、圆角、阴影、动效时长/缓动 SHALL 只有一份权威定义；两个应用与组件库 MUST 引用同一来源，MUST NOT 存在第二份手工同步的 token 副本。

#### Scenario: 修改主题色
- **WHEN** 修改单一来源中的主色值
- **THEN** 玩家端与后台所有引用处同时生效，无需第二处修改

### Requirement: 明暗双主题

每个语义色 MUST 同时具备暗色与亮色取值；主题切换 MUST 即时作用于两端全部组件，且不要求刷新。

#### Scenario: 后台切亮色不影响玩家端默认
- **WHEN** 后台切到亮色主题
- **THEN** 后台界面即时变为亮色，玩家端按自身主题设置独立呈现

### Requirement: 后台所需组件原语覆盖

组件库 MUST 覆盖管理后台所需原语：表格（含加载骨架与行 hover 反馈的等价物）、模态弹窗、标签页导航、状态徽章、赔率筹码（含选中/涨/跌态）、骨架屏、Toast 通知、空状态、SVG 折线图、头像、联赛徽章、离线横幅。

#### Scenario: 后台页面仅用库原语组装
- **WHEN** 审查任一后台面板的实现
- **THEN** 其 UI 元素全部来自共享组件库（或库未覆盖且两端不复用的局部布局），无从旧 Web 应用搬运的独立 CSS 组件
